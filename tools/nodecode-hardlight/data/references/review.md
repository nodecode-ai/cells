# Review: specificity, navigation and craft without a taste score

## Separate four kinds of evidence

1. **Product truth:** source content, actual capabilities, prices, constraints and asset rights. A beautiful invented testimonial still fails.
2. **Structural behavior:** routes, task completion, state handling, keyboard and history. A working button that leads to the wrong task still fails.
3. **Rendered craft:** hierarchy, type, grouping, imagery, color and responsive composition. Clean source is not rendered evidence.
4. **Human fit:** comprehension, confidence, emotional tone and task behavior observed with the intended audience. A reviewer can offer a reasoned judgment but cannot fabricate user research.

For each finding record the location/state, observation, consequence, proposed change, severity and evidence. Use **blocker**, **material improvement** or **deliberate tradeoff** rather than a numeric beauty/slop score. Label automation, visual review, publisher account and user observation distinctly.

## The no-slop review

| Question | Failure signal | Required correction |
| --- | --- | --- |
| Does the first view belong to this subject? | Swapping the name leaves the same hero, feature tiles and closing CTA | Rebuild around a real object, operation, argument or asset |
| Is there one coherent organizing idea? | Every section introduces a different fashionable effect | Keep a material/compositional rule and remove unrelated gestures |
| Does content create the form? | Equal card grids flatten unequal ideas; placeholder icons stand in for evidence | Choose a list, ledger, diagram, spread, scene or another task-relevant structure |
| Is identity present beyond the hero? | Generic forms, errors and mobile screens contradict the opening | Apply the same type, language and state grammar to utility surfaces |
| Are claims and artifacts real? | Invented metrics, client logos, testimonials or unlabeled demo records | Replace with sourced truth or clearly identified illustrative material |
| Can every visible control keep its promise? | Decorative search, nonfunctional tabs, empty modal buttons | Implement the actual behavior, remove the control or explain a real limitation |
| Can a visitor orient and recover? | Clever labels, hidden current location, lost filters, dead-end detail | Correct navigation and history before surface polish |
| Was the narrow view composed? | A desktop hero merely shrinks; menus lose labels; art vanishes | Reorder and recrop while preserving the central idea and task |

These are context-sensitive prompts, not style bans. A card grid can be correct for comparable objects; glass, gradients, serif, monospace, green or purple can be precise choices. Ask what they do here, not whether a prohibited pattern appears. Minimal work still needs authorship; maximal work still needs order.

## Review in useful passes

**Task pass:** start from a realistic entry, identify current scope, reach the main action, complete it, recover from a failure and return. Test a direct detail URL and Back/Forward. Check a permission-limited state. Graph reachability supports this pass but cannot certify label comprehension.

**Composition pass:** inspect the initial wide and narrow states, then one engaged state. First identify the primary/secondary hierarchy and dominant visual idea. Next inspect line lengths, alignment, grouping, crop, asset resolution and visual rhythm. Check whether repeated containers are justified by content. Compare against the committed design premise, not a reviewer's favorite house style.

**Resilience pass:** keyboard, focus, touch, reduced motion, slow/missing assets, long text, zoom and errors. Automated contrast and DOM findings are partial; manually inspect unresolved backgrounds and semantics. Verify real controls do not merely change a screenshot.

Batch material fixes, then perform a confirmation pass on the affected states. Do not restart the whole design for every local imperfection. If the premise fails the task, revise it explicitly rather than polishing the wrong structure indefinitely.

## Handoff language

Report “three task paths exercised at these widths; these states remain untested,” not “fully usable.” Report “original atlas and working examples,” not “empirically better than another design system.” Include the artifact, exact checks performed, unresolved risks and decisions intentionally accepted. Awards, lint results and screenshots do not establish task success or a comparative quality benchmark.
